# VaultFS feature matrix

Status describes source evidence, not runtime confidence. **Complete** means complete in source; no VaultFS feature qualifies as end-to-end complete here. Test status reflects usable automated coverage, not files with “test” in the name.

| Feature / requirement | Status | Evidence and frontend | Backend / integration | Tests | Issues and priority |
|---|---|---|---|---|---|
| Product web application | Missing | Only starter at `apps/web/app/page.tsx`; no dashboard routes. | API separate; no web integration. | None. | P0: deliver product shell after core API stabilizes. |
| Session authentication | Partial | No login UI. | Better Auth configured in `packages/auth/src/server/auth.ts`; catch-all mounted in `apps/api/src/routes/auth/better-auth.ts`; `requireAuth` validates sessions. Cookie logging removed; proxy trust is disabled by default. | Real PostgreSQL HTTP tests cover login, logout and expiry. | Login UI and deployment-proxy validation remain. |
| Password management | Partial | Missing. | Better Auth credentials; admin create/reset use its password hash and local credential issuer. Null issuers are backfilled additively. | Real PostgreSQL tests cover create/login/reset and a legacy null-issuer fixture. | Email reset delivery and OAuth are not validated. |
| Roles (SuperAdmin/Admin/User) | Partial | No UI. | Global roles remain in `packages/rbac`; resource roles are separate Dockyard membership values. Global Admin does not bypass membership. | Real API tests cover role denials and Admin isolation. | Continue least-privilege review for future API/file actions. |
| Permission authorization | Partial | N/A. | Global `authorize` remains for global operations; `dockyard-access.ts` evaluates actor, target, and action using Dockyard membership. Super Admin global access is audited. | White-box role matrix and real HTTP cross-Dockyard tests. | File/API-key routes must call these policies when implemented. |
| Warehouse management | Partial | No page. | Dockyard is Warehouse. Existing `Dockyards` IDs/relations are retained; creator becomes OWNER. | Warehouse assignment/isolation | Partial | No UI. | `DockyardMember` has OWNER/MANAGER/VIEWER roles. | API-key generation/storage/validation/revocation | Partial | No UI; external onboarding is documented in `docs/API_INTEGRATION.md`. | Session-protected Owner/Manager/audited Super Admin routes issue, list, inspect, rotate and revoke keys in the existing `Api` model. Strict `X-API-Key` middleware validates digest, scope, expiry, revocation, Dockyard status and route binding. | Unit and real PostgreSQL HTTP tests cover creation, one-time disclosure, scopes, viewer/admin denial, isolation, invalid/expired/revoked keys, rotation, inactive Dockyard and concurrent revocation/use. | No dashboard or file routes consume keys yet. Add shared rate limiting and operational key rotation policy before production scale. |

| Download | Partial | No file listing/download UI. | API-key `READ` or session Dockyard download authorization streams only AVAILABLE files with safe attachment headers. | HTTP/PostgreSQL and filesystem tests pass. | No range requests; deployment storage is local volume. |
| Delete | Partial | No UI. | `DELETE` scope or session policy; DELETING then physical removal and retained DELETED metadata tombstone; explicit reconciliation. | Reconciliation and concurrent deletion integration tests pass. | A download already in progress cannot be recalled. |
| Metadata | Partial | N/A. | Existing `DockyardFile` metadata is used; list/detail routes and pagination added; bytes remain outside PostgreSQL. | Additive QUARANTINED enum migration applied to disposable PostgreSQL; integration passes. | Production deployment must apply migration before API rollout. |
| Verification/checksum | Partial | No UI. | SHA-256 is streamed on upload and verification; mismatch quarantines. | Unit and real API integration tests pass. | Operational reconciliation required after crashes. |
| Temporary signed URLs | Partial | No UI. | HMAC token binds Dockyard/file/expiry, maximum one hour, state checked at consumption; token path redacted in logs. | Policy and real PostgreSQL HTTP tests pass. | Bearer link cannot be individually revoked before expiry. |

### Verification distinction

Status reflects source through Checkpoint 4. Its additive migration and real PostgreSQL tests pass in the disposable test environment; see `docs/CHECKPOINT_4_REPORT.md`. “Partial” means dashboard and production operations remain incomplete.
